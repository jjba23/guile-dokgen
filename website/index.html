BASIC USAGE

❶ Document your source code in Texinfo format (see an example).

❷ Extract the documentation with Guile Dokgen.

# Save API documentation of a Scheme module to doc/api/index.texi (default)
dokgen api somelibx.scm

# Or the API documentation of a Scheme directory
dokgen api someliby

# Or the API documentation of one or more related sources
dokgen api "somelibz.scm somelibz"

# You can also save the API documentation to any directory
dokgen api mylib --destination mydocs/api

❸ Include the generated API docs in the main Texinfo file of your project documentation. For example: 

@include api/index.texi
❹ Build your project documentation (using texi2any, for example).

Docstrings are Texinfo, so they can carry a diagram as a fenced mermaid block: it is drawn through a renderer of your choice and shown as an image, or written as its source when no renderer is installed. 

# Draw the diagrams your docstrings hold (the default renderer is mmdc)
dokgen api somelibx --mermaid-command "mmdc --input %i --output %o.png --scale 2 --backgroundColor transparent"

# Fail the build when an exported procedure has no docstring
dokgen check somelibx

# Measure the tree and write a chapter of numbers about it
dokgen stats somelibx --destination doc/api

Every definition also carries an anchor built from its module and its name, so a chapter written by hand can point at one procedure with @ref{dokgen_cli_call} — and the stylesheet and script written beside the chapter turn those definitions into cards with an index you can filter, signatures you can copy, details you can fold and diagrams you can zoom. This manual is an example: its API chapter is that output.

Check out Guile Dokgen Manual for more information. Its API section is itself an example of the API structure generated by Dokgen.

INSTALLATION

Guile Dokgen can be installed on any GNU/Linux device using the GNU Guix package manager. 

guix install guile-dokgen

Once installed, you can start using the dokgen program.
