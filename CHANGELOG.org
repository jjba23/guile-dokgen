Notable changes, newest first.  Releases before 0.5.0 were made by the
original author; their record is the version history in the manual.

* 0.11.0 — 2026-11-22

** Added

- A split manual's API chapter landing page explains what the chapter holds
  and how to read it, instead of leaving the page empty once its module list
  moves into the index.

** Fixed

- Without JavaScript, the page keeps a readable column, its body table of
  contents and navigation, and source blocks that scroll instead of widening
  the page.


* 0.10.2 — 2026-11-22

** Fixed

- The Nix derivation quotes the launcher's PATH change, so the wrapper the
  install phase writes is a valid shell script.


* 0.10.1 — 2026-11-22

** Fixed

- Gnuplot plots are drawn again with the default command: the wrapper asked
  for a transparent background, which gnuplot 6 refuses, so a plot without a
  committed image fell back to source.  The SVG terminal is transparent by
  default and the wrapper no longer asks.


* 0.10.0 — 2026-11-22

** Added

- Mermaid diagrams no longer need a renderer to be read: when no image was
  drawn, the chapter carries the diagram's source and a marker, and the
  page draws it from a bundled Mermaid 11.4.1.  ~mmdc~ is still used when
  it is installed, but a project that only builds HTML does not have to
  install it or add a build step.
- Gnuplot diagrams: a fenced ~gnuplot~ block in a docstring is written
  beside the chapter and drawn as SVG when ~gnuplot~ is on the ~PATH~.
  The new ~--gnuplot-command~ option replaces the command; the default is
  ~gnuplot %i~.  Without gnuplot the plot stays readable as source.
- The bundled Mermaid renderer is written beside the chapter as
  ~dokgen-mermaid.js~, and only a page that carries a diagram loads it.

** Changed

- The HTML page is one page a reader can navigate on any screen.  The
  chapter no longer lists its modules below the heading, where the table of
  contents beside the page already listed them: the index now follows the
  page's headings down to every definition, and it is the only table of
  contents in the reading view -- on a single-page manual the body's own
  table of contents goes too, since the index holds the whole manual.  On a
  narrow screen it becomes a drawer behind a button, and a bar keeps the
  page's title, the theme and a way back to the top.
- The page is warmer and quieter: serif headings on warm neutrals, a
  calmer index whose top level is open, quieter cards, and less furniture.
  The diagram lightbox and the folded tail of long definitions are gone;
  a definition reads in place and a diagram fits the column.
- The chapter opens with a sentence about what it documents -- the name the
  modules share, how many modules there are and how many names they export
  -- instead of a paragraph about dokgen's own stylesheet.
- A record type and a record are described in one sentence with their
  fields instead of a bullet list.  A variable whose value is a string too
  long to read is described by its length, which keeps the stylesheet and
  the script from burying the rest of the reference.

** Fixed

- The scanners behind ~dokgen stats~ keep the lines of a string or a block
  comment that spans several of them, instead of taking the newline with the
  escape.  A file with one such line was counted with fewer lines of code than
  it has; the suites now hold a case for each.


* 0.9.0 — 2026-11-21

** Added

- The HTML a reader arrives at is built to be read.  ~dokgen api~ and
  ~dokgen stats~ now write ~dokgen.css~ and ~dokgen.js~ beside the chapter they
  generate: a card for each definition with its signature at the top, an index
  of those definitions down the side with a filter, a button that copies a
  signature, a folded tail on the long definitions, a light and a dark page
  that follow the reader's own preference, and diagrams that open into a
  viewer with zoom and drag.  Both files are progressive and hold no
  dependency: a manual that ignores them gets the same chapter it would have
  had, and Info and print never see them.
- Every module section opens with an *Overview*: the names the module exports,
  each linked to its own definition and followed by the sentence that
  documents it, so a reader looking for one of them scans a list and not a
  chapter.
- ~maak manual~ points this project's HTML at both files, so the published
  manual is the example the manual talks about.

** Changed

- Diagrams are drawn at twice the size they are shown at and with no
  background (~--scale 2 --backgroundColor transparent~ is the new default
  renderer command), so that they stay sharp on a page of any width and on a
  page that is dark.

* 0.8.0 — 2026-11-21

** Added

- ~dokgen stats~, which measures a tree and writes the result as a Texinfo
  chapter: the lines of code, of comment and of nothing, the bytes, the
  modules the files make, how much of the exported API carries a
  documentation string, what each author added and removed, and which of the
  measured files churn the most.  The chapter is a snapshot that names the
  commit it describes, so a manual can include it and a reader can tell how
  old the numbers are.
- The tree that dokgen documents is measured the same way: ~maak docs~ now
  regenerates ~manual/api/stats.texi~ beside the API reference, the manual's
  new *Statistics* chapter includes it, and ~maak release~ takes both again
  after it writes the version.
- Decision points: how often a form that branches or loops is opened in the
  code, counted after comments and strings are stripped, so a branch written
  inside a string is not a branch.  It counts shapes and not paths, and it
  grades nothing.

** Changed

- Source scanning is one place: the list of files a command works on, and
  the directory the modules are named from, come from one helper instead of
  being computed twice.


** Fixed

- ~guix.scm~, the package definition of the working tree, evaluates again: it
  named ~git-predicate~ and ~guile-proba~ without importing their modules, was
  missing a closing parenthesis, added its launcher to a phase
  ~guile-build-system~ does not have, and wrote a launcher that could not find
  the modules it had just installed.  ~guix shell -f guix.scm -- dokgen --help~
  works as the file says it does.

* 0.7.0 — 2026-11-21

** Added

- Mermaid diagrams in the documentation: a fenced block in a docstring or a
  module's commentary is drawn and shown in the manual, or written as its
  source when no renderer is at hand.  The new ~--mermaid-command~ option says
  what draws them (default ~mmdc --input %i --output %o.png~), and an empty one
  means "use the images already there".  Each diagram is written as
  ~diagrams/NAME-HASH.mmd~ with its image beside it, the hash being a digest of
  the diagram's own text, so a stale drawing is never shown as the current one.
- ~dokgen check~, which reports every exported procedure and macro that has no
  documentation string and exits non-zero when it found one, so a build can
  hold a library to a documented API.
- Every definition carries an ~@@anchor~ built from its module and its name, so
  a hand-written chapter can ~@@ref~ a single procedure.  The Texinfo bug this
  used to wait on, 72209, is fixed in the version the project builds with.
- The API chapter opens with the list of modules it documents, each one a link.

** Fixed

- An ~@@image~ or an ~@@itemize~ no longer runs into the text that follows it,
  and an anchor no longer shares a line with the definition it names;
  ~texi2any~ warned about both.

* 0.6.2 — 2026-11-17

** Changed

- Every definition is documented in Texinfo: the exceptions, commands, cli and
  utils modules have a commentary describing their exported names, internal
  helpers have docstrings instead of comments, and the generated API reference
  includes them.
- CONTRIBUTING states the docstring format.

* 0.6.1 — 2026-11-17

** Changed

- Rebranded: a new icon, wordmark and project page replace the original
  author's artwork, so the whole tree is MIT and nothing carries another
  license.  ~designs/website.svg~ and the old images are gone.
- The manifest names its packages instead of importing their modules, which
  fixed the CI gates failing on an unbound ~guile-proba~, and ~maak check~ now
  runs its whole script.

* 0.6.0 — 2026-11-17

** Changed

- One version, quoted everywhere: ~src/dokgen/cli.scm~ states it and ~maak
  release~ rewrites the manual's ~@set VERSION~, the README badge and the
  website; ~maak version-check~ fails when one drifted.
- The project page and the HTML manual use the jointhefreeworld look.
- CI gates the version, compilation, tests, the generated API reference and the
  manual, and deploys the page; a new release workflow publishes a tag's GitHub
  release from its changelog section.
- Renamed from guile-documenta to guile-dokgen.  The program is now ~dokgen~
  (launcher ~bin/dokgen~), the modules are ~(dokgen ...)~ under ~src/dokgen/~,
  the load-path variable is ~DOKGEN_LOAD_PATH~ and the Guix package is
  ~guile-dokgen~.  This breaks every caller of ~documenta~ and ~(documenta ...)~.

* 0.5.0 — 2026-11-17, hard fork

** Changed

- The project is now a hard fork under new maintainership.  The license changed
  from the public domain to the MIT License; every source file carries an SPDX
  header and ~LICENSE~ holds the text.  The original author is credited in the
  README and the manual.
- The layout follows [[https://github.com/jjba23/sift][sift]]: sources in ~src/~, the launcher at ~bin/dokgen~
  (replacing ~dokgen.scm~), helpers in ~etc/~.
- Development moved to Maak (~maak.scm~) running in a pinned Guix
  (~channels.scm~ for ~guix time-machine~, ~manifest.scm~, ~guix.scm~), replacing
  ~build-manual.sh~.
- The website and the manual no longer point at the original author's pages.

** Added

- ~AGENTS.md~, generated by ~maak agents~, and ~CONTRIBUTING.md~.
- ~etc/run-test.scm~, so a failing SRFI-64 suite fails ~maak test~.
